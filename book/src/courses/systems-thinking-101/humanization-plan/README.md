## 📋 What This Project Is

The Systems Thinking 101 course has high-quality technical content, but it reads like it was generated by AI. This project will humanize the content by:

- Removing formulaic, repetitive patterns (e.g., "What is/What Are [Topic]?")
- Adding conversational elements (questions, stories, transitions)
- Varying structure and tone naturally
- Making quizzes more engaging and varied
- Creating a reading experience that feels like learning from a mentor, not a machine

**The result:** A course that's not just clearer and more engaging—it actually feels human.

## 📝 How to Rewrite a Lesson

### Before You Start

1. **Open the original lesson file**
2. **Open 05-QUICK_REFERENCE.md** in another window
3. **Open 02-MODULE1-LESSON1-REWRITE.md** for reference
4. **Decide which template applies:**
   - Template A: Concept Introduction (new core concepts)
   - Template B: Practical Application (how-to, step-by-step)
   - Template C: Advanced Concept (deep dives, types/categories)

### Step-by-Step Process (90 minutes)

**1. Read & Plan (15 min)**
- Read the original lesson
- Identify which template to use
- Choose varied headings (use 05-QUICK_REFERENCE.md)
- Plan your opening hook (question or story)

**2. Write Opening (20 min)**
- Start with a hook (NOT a definition)
- Write 2-3 paragraphs of prose
- Add a transition to the first example
- Check: Does this sound like a human wrote it?

**3. Rewrite Examples (25 min)**
- Keep the Sruja code unchanged
- Add conversational explanations around code
- Add "What this shows" or "Notice how..." sections
- Use transitional phrases between examples

**4. Rewrite Middle Sections (20 min)**
- Vary headings (not all "Types of X", "Why X Matters")
- Add misconceptions, tips, or patterns as needed
- Write in paragraphs, not just bullets
- Add conversational transitions

**5. Rewrite Summary (10 min)**
- Change "Key Takeaways" to "What to Remember" or similar
- Write as paragraphs, not a bullet list
- Make it personal and encouraging

**6. Rewrite Quiz (15 min)**
- Vary question formats (not identical HTML)
- Add 1-2 open-ended reflection questions
- Write explanations that teach, not just state answers
- Make it feel like a conversation

**7. Add "What's Next" (5 min)**
- Link to the next lesson
- Preview what's coming
- Explain why it matters

**8. Review (10 min)**
- Use the checklist in 05-QUICK_REFERENCE.md
- Read aloud to catch robotic phrasing
- Validate Sruja code with `sruja lint`
- Save your work

## ✅ Quality Checklist

Before marking a lesson complete, verify:

### Structure
- [ ] Frontmatter summary is engaging (question or hook, not just description)
- [ ] Uses "Learning Goals" (plural), not "Learning Goal" (singular)
- [ ] Main heading varies (NOT "What is/What Are [Topic]?")
- [ ] Section headings vary appropriately
- [ ] Has conversational transitions between major sections
- [ ] Mixes paragraphs and bullet points (aim for 60:40 ratio)
- [ ] Section lengths vary naturally (not perfectly symmetric)
- [ ] Has "What's Next" section linking to the next lesson

### Content
- [ ] Starts with a hook (question, story, or relatable scenario)
- [ ] Uses concrete, real-world examples
- [ ] Explains *why* something matters, not just *what* it is
- [ ] Avoids over-structuring simple explanations in code blocks
- [ ] Sruja code examples are accurate

### Voice & Tone
- [ ] Uses second person ("you") consistently
- [ ] Has 3+ rhetorical questions
- [ ] Has conversational tone (not academic or overly formal)
- [ ] Avoids AI-typical phrases ("In conclusion," "Furthermore," "It's important to note")
- [ ] Uses first-person occasionally ("Let me share...", "I've seen...")
- [ ] Has encouraging language

### Quizzes
- [ ] Question formats vary (not identical HTML for every question)
- [ ] Includes open-ended or reflection questions
- [ ] Explanations feel natural, not robotic
- [ ] Answers provide context, not just the letter

### Overall
- [ ] Would a human mentor speak this way?
- [ ] Does it feel like a conversation, not a lecture?
- [ ] Is there variety in structure and tone?
- [ ] Would I want to learn from this?

## ⚠️ Common Pitfalls & Solutions

| Pitfall | Solution |
|---------|----------|
| Taking too long per lesson | Use templates rigorously. Aim for "good enough" not perfect. |
| Losing consistency across lessons | Review against style guide and Module 1 Lesson 1 every 2-3 lessons. |
| Sruja code becomes inaccurate during rewrite | Keep original code blocks intact, only modify prose around them. Validate with `sruja lint`. |
| Losing technical accuracy while improving readability | Have original open alongside rewrite. Compare key technical statements. |
| Running out of creative heading variations | Use the Heading Variations Bank in 05-QUICK_REFERENCE.md. |
